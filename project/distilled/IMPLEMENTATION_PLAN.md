**Six Python files, ~650 lines.** `negatives.py` is the only file containing anything new.

### What each file does

| File | Input | Output | ~Lines |
|---|---|---|---|
| `prepare_data.py` | HF dataset id | `data/*` | 90 |
| `negatives.py` | `data/train_pairs.tsv`, `data/dup_groups.json`, `--strategy`, `--k`, `--hard-fraction` | neighbour lists (cached to `data/nb_*.json`) + the batch sampler class | 120 |
| `train.py` | pairs, sampler, CLI args | `runs/<name>/final` (a saved `SentenceTransformer`) | 90 |
| `evaluate.py` | `data/*`, a model name **or** a path | `results/metrics.json` (appended) + per-query rankings | 140 |
| `analyze.py` | `results/*_rankings.json` | FN annotation sheet, error table, 3 figures | 110 |
| `utils.py` | — | seeding, `encode()`, three metrics, bootstrap, jsonl I/O | 100 |

`evaluate.py` accepts **either** a HuggingFace model name (baselines) **or** a local path
(fine-tuned checkpoints), so every system goes through literally the same code.

## 3. Implementation steps

### Step 0 — Environment (30 min)

Colab → Runtime → T4 GPU. `!nvidia-smi`. `pip install -r requirements.txt`.
Verify `SentenceTransformer('all-MiniLM-L6-v2').encode(["hello"]).shape == (1, 384)`.

### Step 1 — `prepare_data.py` (half a day)

```python
from datasets import load_dataset
ds = load_dataset("sentence-transformers/askubuntu")
# train 12745 / dev 200 / test 200; each row: query, positive[], negative[]
```

1. **Corpus:** `sorted(set(all queries) | set(all positives))` → ~13,000–15,000 docs. Print it.
2. **Queries:** the 400 dev/test `query` fields, ids `"dev-0"…"test-199"`, split recorded.
3. **Qrels:** `qrels[qid] = [corpus_id(p) for p in row['positive']]`. Assert every positive is in
   the corpus. Print mean golds per query (expect ~1–2).
4. **Train pairs:** one `(query, p)` per `p` in each **train** row's `positive`. Print the count
   (expect ~17,000–20,000).
5. **Duplicate groups:** `dup_groups.json` — for each train anchor, the set of texts in its
   duplicate group (its positives, and transitively their positives if you want; the direct
   lists are enough). **`negatives.py` needs this to keep known duplicates out of
   neighbourhoods.**
6. **Leakage check:** no train anchor or train positive appears among the 400 eval query texts.
   Print PASS/FAIL. If it fails, stop.
7. Write all six files.

### Step 2 — `utils.py` (1 hour)

`set_seed`; `load_jsonl`/`load_json`; `encode(model, texts, bs=256, normalize=True)`;
`recall_at_k`, `mrr_at_k`, `ndcg_at_k`; `retrieve(query_vec, corpus_matrix, exclude_ids, k)`;
`paired_bootstrap(deltas, n=10000)` → (lo, hi).

### Step 3 — `evaluate.py` (half a day)

For each system: score every corpus document for each eval query (BM25 via `rank_bm25`; dense via
one matmul), **mask the query's own corpus id**, take the top 10, accumulate the three metrics.
Write `results/metrics.json` (append, keyed by run id) and a per-query ranking dump for
`analyze.py`.

Two details that matter:
* **Cache corpus embeddings** to `results/embeddings-<name>.npy`. You will re-evaluate ~15 times.
* **Mask self.** Eval queries are themselves corpus documents. Without masking, every query
  retrieves itself at rank 1 with score 1.0 and all three metrics read ~100%.

### Step 4 — Baselines, before any training (half a day)

```bash
python src/evaluate.py --system bm25              --split dev
python src/evaluate.py --system bm25              --split test
python src/evaluate.py --system all-MiniLM-L6-v2  --split dev
python src/evaluate.py --system all-MiniLM-L6-v2  --split test
```

Rows B1 and B2 done. **Do not proceed until these survive all twelve checkpoints in §6.**

### Step 5 — `negatives.py` (one day — the only hard file)

```python
def build_neighbourhoods(anchors, strategy, dup_groups, k=64, model=None):
    """Return {anchor_idx: [neighbour anchor indices]}, length <= k.
    N2: top-k by BM25 among training anchors (rank_bm25).
    N3: top-k by cosine of zero-shot MiniLM embeddings (one matmul).
    In BOTH: drop the anchor itself and every anchor in its duplicate group."""
```

```python
class NeighbourhoodBatchSampler:
    """__iter__ yields lists of pair indices, one list per step.
    Each batch = 1 seed pair + (B-1) others;
    round(hard_fraction * (B-1)) drawn from the seed's neighbourhood pair set,
    the rest sampled uniformly (excluding the seed's duplicate group).
    Regenerated each epoch with RNG seed = seed + epoch.
    __len__ = epochs * ceil(n_pairs / B)."""
```

Then:

```python
loader = DataLoader(train_examples, batch_sampler=sampler,
                    collate_fn=model.smart_batching_collate)
model.fit(train_objectives=[(loader, losses.MultipleNegativesRankingLoss(model))],
          epochs=1, warmup_steps=..., optimizer_params={"lr": 2e-5})
```

The classic `model.fit` API gives you full control over the DataLoader, which is what you need
for a custom batch sampler. If you prefer `SentenceTransformerTrainer` and its `batch_sampler`
argument cooperates, use that instead — but do not spend more than two hours on the plumbing.

**N1 is just `hard_fraction=0.0`** — the sampler degenerates to a random shuffle. That means all
three conditions run through identical code, which is the point.

Cache neighbour lists to `data/nb_bm25_k64.json` and `data/nb_model_k64.json` so you build them
once.

### Step 6 — `train.py` (half a day)

Flags: `--negatives {random,lexical,model} --hard-fraction F --epochs E --batch-size B --lr LR
--seed S --out DIR`. Fixed: `B=32`, `k=64`, `lr=2e-5`.

Expected wall-clock: **~5 minutes per run.** ~19,000 pairs ÷ 32 ≈ 600 steps/epoch. If a run
exceeds ~30 minutes on a T4, check `max_seq_length` (short questions padded to 256 wastes
everything).

### Step 7 — The experiments (week 3)

```bash
# --- epoch selection on dev, using N1 only ---
for e in 1 2 3; do
  python src/train.py --negatives random  --epochs $e --seed 42 --out runs/N1-e$e-s42
  python src/evaluate.py --system runs/N1-e$e-s42/final --split dev
done
# → E = best epoch count, reused for every condition below

# --- three conditions × three seeds on test ---
for neg in random lexical model; do for s in 13 42 1337; do
  python src/train.py --negatives $neg --epochs $E --seed $s --out runs/$neg-e$E-s$s
  python src/evaluate.py --system runs/$neg-e$E-s$s/final --split test
done; done

# --- ablation: the hardness dial, on N3, dev ---
for f in 0.25 0.5 1.0; do
  python src/train.py --negatives model --hard-fraction $f --epochs $E --seed 42 \
      --out runs/N3-f$f-s42
  python src/evaluate.py --system runs/N3-f$f-s42/final --split dev
done
```

9 + 3 + 2 = **14 runs** (plus 3 optional: a second encoder on the winning condition). ~2 hours
of GPU in total. Put it all in `experiments/run_all.sh`.

### Step 8 — Statistics and analysis (week 4)

```bash
python src/evaluate.py --contrast runs/N1-e$E-s42/final vs all-MiniLM-L6-v2 --split test
python src/evaluate.py --contrast runs/N2... vs runs/N1... --split test
python src/evaluate.py --contrast runs/N3... vs runs/N2... --split test
python src/analyze.py --fn-sample 50 --topk 5     # the false-negative annotation sheet
python src/analyze.py --errors 30                 # the 30-query error table
python src/analyze.py --figures
```

`--contrast` computes per-query differences and runs the paired bootstrap (10,000 resamples).

## 5. Reproducibility rules (cheap, do all six)

1. `set_seed(seed)` from the CLI flag; the sampler uses `seed + epoch`.
2. Save every run's full arg set to `runs/<name>/args.json`.
3. Append to `results/metrics.json` keyed by run id — never overwrite.
4. Commit `data/` (a few MB, including the cached neighbour lists) so corpus, splits and
   neighbourhoods are frozen.
5. `experiments/run_all.sh` reproduces every number from a clean checkout.
6. Record the exact `pip freeze` in `results/`.

## 6. Debugging checkpoints — run all twelve in weeks 1–2

| # | Check | Passes when | Catches |
|---|---|---|---|
| 1 | Print 5 random rows per split | real Ubuntu questions; dev/test have 200 rows | wrong dataset or split |
| 2 | `len(corpus)` ≈ 13,000–15,000; every query has ≥1 gold | both true | broken dedupe or text→id mapping |
| 3 | **Leakage:** no train anchor/positive appears among the 400 eval queries | zero overlaps | training on your test set |
| 4 | **Self-exclusion:** no eval query's top-1 is its own text | 0/400 | **the #1 silent killer** — metrics inflated to ~100% |
| 5 | Zero-shot Recall@10 well above chance, far from 100% | ~30–75% | chance (≈0.07%) = broken qrels; >95% = checkpoint 4 failed |
| 6 | BM25 Recall@10 non-trivial | >10% | ≈0 = broken tokenisation or corpus/qrels mismatch |
| 7 | Training loss starts near `ln(32) = 3.47` and falls within ~100 steps | both | wrong loss, wrong data format, or lr wildly off. `ln(N)` is the *exact* value for a uniform softmax — a precise check, not a rule of thumb. |
| 8 | After training: mean cosine of held-out **positives** up; mean cosine of **random** pairs ≈ unchanged | both | **representation collapse** — if every cosine ≈ 1, the model mapped everything to one point |
| 9 | No neighbourhood contains a member of the anchor's duplicate group | 0 violations | **specific to this version** — known duplicates used as negatives, which is a labelling bug masquerading as hardness |
| 10 | Neighbourhood sanity: print 3 anchors with their top-5 neighbours | they look topically similar, and N3's neighbours look *semantically* similar where N2's look *lexically* similar | mining wired to the wrong similarity, or neighbourhoods built on the wrong index space |
| 11 | Hardness sanity: mean in-batch cosine of anchor vs. other pairs' positives | **N1 < N2 < N3** | **the manipulation check.** If the three conditions produce equally hard batches, your independent variable did not vary and the experiment is void. |
| 12 | Same seed twice → identical metrics to 4 dp | yes | nondeterminism that makes the 3-seed spread meaningless |

**Checkpoints 9 and 11 exist only in this version. Do not skip them.** Checkpoint 11 in
particular is the difference between "I ran three conditions" and "I ran three conditions that
actually differed in the way I claim".

## 8. Colab notes

* T4 GPU, free tier, is enough for all 14 runs.
* Save `runs/` and `results/` **outside the notebook** (Drive or the repo). Colab disconnects.
* `fp16=True` on T4; drop it if you get a dtype error — the project is small enough for fp32.
* Commit `data/` including cached neighbour lists. Re-deriving them with a different set ordering
  will silently change your neighbourhoods and therefore your independent variable.
* Put the dataset download behind a local cache check in `prepare_data.py`.

## 9. If you are behind schedule

Cut in this order. Never cut anything below the line you have reached.

1. Drop the `hard_fraction` ablation (saves 2 runs, ~1 day).
4. Drop the false-negative annotation to 25 queries instead of 50.
2. Drop to 2 seeds instead of 3.
3. **Drop N3** — this costs you the most interesting condition but leaves a complete two-condition
   experiment (N1 vs N2), which still has a real independent variable.
5. Drop the third figure.
6. Drop the dev split from the tables.

**If `negatives.py` is not working by day 14:** drop to N1 only. That is Version A
([`SCOPE.md`](SCOPE.md)) — a complete, correct, finishable project with no independent variable.
Shipping Version A is a much better outcome than shipping a half-working N3.

**Never cut:** the leakage check, the self-exclusion check, the duplicate-group filter in the
neighbourhoods, the hardness manipulation check, the BM25 baseline, or the zero-shot control.
